# MODEL.md — 无岸 简化深海生态模型 v0.1

本模型是**机制探索原型**，所有参数都是归一化演示值，没有用真实渔业或深海调查数据校准，不能用于预测。

## 1. 状态与单位

- 三个等体积深度层：L1 600–900 m，L2 900–1200 m，L3 1200–1500 m（场景设定，不代表真实物种分布）。
- 每层 5 个生物量库，顺序固定为 `[R, A, B, C, D]`：

| 库 | 含义 |
|---|---|
| R | 基础饵料：小型甲壳类、浮游动物等可食用饵料的聚合库。**不是**本地光合作用产生的藻类，也不是"海洋雪" |
| A | 偏上层的小型摄食鱼 |
| B | 偏下层的小型摄食鱼 |
| C | 中型捕食鱼 |
| D | 大型捕食鱼 |

- 核心状态 `X[pool][layer]`，共 15 个量。
- 单位：**BU**（归一化碳生物量）。BU 不是千克，也不是鱼的条数。时间单位是**模拟日**。
- 摄食收益代表聚合的生物量生产，不区分个体生长和新个体补充，不模拟繁殖事件、成熟年龄。

## 2. 食物网

捕食偏好矩阵 `a[捕食者][被摄食对象]`，无量纲相对权重（不是捕食概率）：

|   | R | A | B | C | D |
|---|---|---|---|---|---|
| A | 1 | 0 | 0 | 0 | 0 |
| B | 1 | 0 | 0 | 0 | 0 |
| C | 0 | 1 | 1 | 0 | 0 |
| D | 0 | 0 | 0 | 1 | 0 |

- 只在同一层内摄食，层内充分混合，不算距离；层与层之间不能捕食。
- 由此出现：A、B 竞争 R；C 捕食 A、B；D 捕食 C。所有间接效应都来自同一套更新方程，代码里没有任何"D 少了所以 C 增加"之类的脚本。

## 3. 参数（`src/sim/config.ts`）

| 物种 | 初始总量 | q (1/日) | H (BU) | η | m (1/日) | μ (1/日) | 目标分布 p |
|---|---|---|---|---|---|---|---|
| A | 90 | 0.040 | 100 | 0.30 | 0.0030 | 0.010 | 0.70 / 0.25 / 0.05 |
| B | 90 | 0.040 | 100 | 0.30 | 0.0030 | 0.010 | 0.05 / 0.25 / 0.70 |
| C | 20 | 0.025 | 40 | 0.25 | 0.0015 | 0.005 | 0.25 / 0.50 / 0.25 |
| D | 5 | 0.015 | 15 | 0.20 | 0.0008 | 0.005 | 0.10 / 0.30 / 0.60 |

- 鱼类初值 `X[s,k] = 初始总量[s]·p[s,k]`；R 初值 `[100, 100, 100]`。
- R 外部净补给 `J = [1.0, 0.8, 0.6]` BU/日，R 背景损失 `m_R = 0.004`/日，R 不做层间交换。
- `dt = 0.2` 日；`F_max = 0.02`/日；所有捕捞初始为 0。
- `validateConfig` 检查有限值、非负、范围、`p` 之和为 1、R 行为 0；`validateInterventions` 检查 u∈[0,1]、补给倍率∈[0,2]。

**参数未做任何校准**，与题目给定的默认值完全一致（见第 7 节的结果，默认参数下各物种可以共存，不需要调参）。

## 4. 单步更新（`src/sim/flux-step.ts`, `migration.ts`, `simulator.ts`）

对每一层分别计算（省略层下标 k），`h = dt`。所有通量都从**同一份步初快照**计算，最后统一提交。

**① 摄食需求**（`feeding.ts`）

```
Food_i = Σ_j a[i,j]·X_j
U[i,j] = q_i·X_i·a[i,j]·X_j / (H_i + Food_i)          BU/日
```

所以 `Σ_j U[i,j] = q_i·X_i·Food_i/(H_i+Food_i) ≤ q_i·X_i`：多种猎物共享一个摄食上限。食物为零时摄食为零。

**② 统一移除**

```
OutRate_j = Σ_i U[i,j] + m_j·X_j + F_j·X_j
Remove_j  = X_j·(1 − exp(−(OutRate_j/X_j)·h))          用 −expm1(−x) 计算
Scale_j   = Remove_j / OutRate_j
C[i,j]        = U[i,j]·Scale_j          实际摄食量
Background_j  = m_j·X_j·Scale_j
Catch_j       = F_j·X_j·Scale_j
```

`X_j = 0` 或 `OutRate_j = 0` 时本步各项为 0。恒有 `ΣC + Background + Catch = Remove ≤ X_j`：所有捕食者和捕捞共享同一份可用库存，移除量不可能超过库存，因此**不需要任何 clamp**。

这是每个小步内冻结速率后的数值格式，不是非线性系统的精确解，误差用缩小 dt 来检查（第 7 节）。

**③ 提交**

```
鱼类：X'_i = X_i − Remove_i + η_i·Σ_j C[i,j]
R   ：X'_R = X_R − Remove_R + J_k·(补给倍率)·h
```

- 捕食者增长用实际摄食量 C，不用需求量 U。
- 没有额外的 `r·B` 或 Logistic 增长项；没有摄食就没有增长。
- 本步的收益和补给在提交后才进入库存，不能被同一步里的其他物种再次利用。

**④ 层间再分配**（第六节）

```
T_s   = Σ_k X'[s,k]
θ_s   = 1 − exp(−μ_s·h)
X''[s,k] = (1−θ_s)·X'[s,k] + θ_s·p[s,k]·T_s
```

三层同时从同一快照计算，只重新分配、不创造也不销毁生物量；每层净变化记入账本 `migration`。这只是向偏好深度分布的缓慢趋近，不是游泳路径、昼夜垂直迁移或觅食行为。

**⑤ 捕捞**（`fishing.ts`）：选中物种 × 选中层 `F = u·F_max`，其他为 0，R 永远为 0。u 是持续损失率的强度，不是"每次捕获百分比"。停止捕捞只把 F 归零，不恢复库存、不补鱼。

## 5. 生物量账本（`ledger.ts`）

```
Unretained = Σ_i (1−η_i)·Σ_j C[i,j]

Total_next − Total_prev = Σ_k J_k·h − ΣBackground − ΣCatch − ΣUnretained
```

- Total 包含所有层的 R、A、B、C、D。
- 背景损失和未保留的摄食部分进入模型之外（分解、呼吸、碎屑、边界输出），**不返还 R**。捕获量离开系统。
- 这是开放系统的生物量收支，不是活体生物量守恒，也不是完整的能量守恒。
- `checkBudget` 每步核对，容差 `1e-10 × max(1, Total)`，只吸收浮点舍入。代码里没有库存上限、最低保有量或自动补鱼。
- 状态校验允许的负值容差为 `-1e-9`（浮点）；实际运行中所有库存都 ≥ 0（最小值见报告）。

## 6. 确定性与表现层隔离

- 生态核心不使用随机数，完全确定。渲染布局用独立的有种子随机数流（`view/common.ts` 的 `mulberry32`），不会影响生态结果。
- `src/sim` 不引用 Three.js、DOM、帧率或相机（有测试检查源码）。
- 界面每帧只决定执行多少个固定 `dt` 步；速度改变的是"每现实秒多少步"，不改变 `dt`。
- 渲染实例数 = 生物量 ÷ 固定的 BU/实例（A、B 0.18，C 0.06，D 0.02），超过总预算（默认 1500）时整体按比例降采样。实例没有独立生物量，创建和销毁都不改变库存。生物量为零不显示；不足一个实例但非零时显示 1 个并标"低"，不代表离散灭绝。

## 7. 简化边界（明确不实现）

逐鱼 Agent、完整 Boids、流体、温盐氧场、复杂地形、连续空间捕食、渔网物理、体型选择性、年龄结构、DEB、亲鱼量、繁殖季节、完整营养盐循环、经济系统。

## 8. 方法背景

捕食项的形式（按偏好矩阵加权的 II 型功能反应、共享摄食上限）和捕捞死亡率的写法参考了 mizer 的说明文档（setInteraction、getFMort、model description）。本项目实现的是上面规定的**自定义简化模型**，不是 mizer、OSMOSE 或经过校准的深海模型。
