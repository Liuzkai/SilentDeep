二、生态状态与单位

整个水体分为三个等体积深度层：

L1：600–900 m
L2：900–1200 m
L3：1200–1500 m

这些深度只是默认场景设定，不代表真实物种的实测分布。

每一层保存五个生物量库：

R：基础饵料
A：偏上层的小型摄食鱼
B：偏下层的小型摄食鱼
C：中型捕食鱼
D：大型捕食鱼

核心状态为：

X[pool][layer]

pool 顺序固定为：
[R, A, B, C, D]

一共只有 15 个核心生态状态量。

所有库存统一使用归一化碳生物量单位 BU。
所有速率以“模拟日”为时间单位。

BU 不是千克，也不是鱼的条数。
界面不得将生物量或渲染实例数标成真实鱼类数量。

鱼类的摄食收益代表聚合的生物量生产。
本版不区分个体生长和新个体补充，不模拟明确的繁殖事件。
不能据此宣称某物种经过几天完成成熟或繁殖。

R 表示小型甲壳类、浮游动物等可食用基础饵料的聚合库。
R 的外部补给用于近似未显式模拟的下层食物网生产和域外输入。
不要把 R 解释为本地光合作用产生的藻类，
也不要把海洋雪直接解释成所有鱼都能摄食的食物。


三、食物网

使用可配置的捕食偏好矩阵 a。

行是捕食者，列是被摄食对象：

              R   A   B   C   D
A             1   0   0   0   0
B             1   0   0   0   0
C             0   1   1   0   0
D             0   0   0   1   0

矩阵数值是无量纲的相对摄食权重，不是每步捕食概率。

只允许同一深度层内发生摄食。
层内采用充分混合近似，不计算鱼群之间的实际距离。
不同深度层之间不能直接捕食。

由此自然产生：
A 与 B 对 R 的资源竞争；
C 对 A、B 的捕食；
D 对 C 的捕食；
捕捞 D 后可能产生向下传递的间接反馈。

禁止为这些结果写剧情脚本或强制增减其他物种。
所有变化必须来自统一更新方程。


四、默认参数

以下全部为归一化演示参数，不是真实鱼类测量数据。

参数含义：

q：单位捕食者生物量的最大摄食率，单位 1/模拟日
H：半饱和饵料量，单位 BU
eta：摄食量转化为本模型活体生物量的比例，无量纲
m：背景生物量损失率，单位 1/模拟日
mu：层间分布调整率，单位 1/模拟日
p：三个深度层的目标分布权重，和为 1

物种参数：

物种   初始总生物量   q       H     eta    m        mu
A      90             0.040   100   0.30   0.0030   0.010
B      90             0.040   100   0.30   0.0030   0.010
C      20             0.025   40    0.25   0.0015   0.005
D      5              0.015   15    0.20   0.0008   0.005

目标深度分布：

p_A = [0.70, 0.25, 0.05]
p_B = [0.05, 0.25, 0.70]
p_C = [0.25, 0.50, 0.25]
p_D = [0.10, 0.30, 0.60]

鱼类初始分层生物量：
X[s,k] = 初始总生物量[s] * p[s,k]

R 的初始分层生物量：
[100, 100, 100]

R 的外部净补给 J，单位 BU/模拟日：
[1.0, 0.8, 0.6]

R 的背景损失率：
m_R = 0.004 /模拟日

R 不进行层间交换。

所有捕捞强度初始为零。
默认生态时间步：
dt = 0.2 模拟日

所有参数集中在一个有类型检查和数值校验的配置模块中，
不要散落在渲染代码或界面事件中。


五、核心生态算法

采用同一状态快照计算所有通量，再统一提交更新。
禁止一边遍历物种，一边直接修改其他物种库存。

以下过程对三个深度层分别计算。
为简洁省略层下标 k。
令 h = dt。

1. 计算摄食需求

对于捕食者 i，i 属于 A、B、C、D：

Food_i = sum_j(a[i,j] * X_j)

对每一种被摄食对象 j：

U[i,j] =
    q_i * X_i * a[i,j] * X_j
    / (H_i + Food_i)

U 的单位为 BU/模拟日。

这意味着：

sum_j U[i,j] <= q_i * X_i

食物为零时摄食为零。
猎物再丰富，单位捕食者的摄食也不能超过上限。
多个可食用物种共享这个摄食上限，
不能针对每种猎物各获得一次完整的最大摄食量。

U 只是需求速率，实际摄食量还需要根据猎物库存统一分配。


2. 同时处理捕食、背景损失和捕捞

F_j 是物种 j 在当前层的捕捞损失率。
R 的 F 永远为零。

对每个生物量库 j：

OutRate_j =
    sum_i U[i,j]
    + m_j * X_j
    + F_j * X_j

如果 X_j 为零，或者 OutRate_j 为零，
则本步 Remove、实际摄食、背景损失和捕捞量全部为零。

否则：

Remove_j =
    X_j * (1 - exp(-(OutRate_j / X_j) * h))

实现时优先使用 -expm1(-x) 提高小数值稳定性。

Scale_j = Remove_j / OutRate_j

本步实际捕食量：

C[i,j] = U[i,j] * Scale_j

本步背景损失：

Background_j = m_j * X_j * Scale_j

本步捕获量：

Catch_j = F_j * X_j * Scale_j

因此：

sum_i C[i,j] + Background_j + Catch_j = Remove_j

所有捕食者和捕捞共享同一份可用库存，
本步总移除量不得超过该库存。

这是每个小时间步冻结速率后的数值更新，
不是完整非线性生态系统的解析精确解。
必须通过缩小时间步检查误差。


3. 统一更新生物量

对鱼类 i：

Gain_i = eta_i * sum_j C[i,j]

X_next_i = X_i - Remove_i + Gain_i

对基础饵料 R：

X_next_R = X_R - Remove_R + J_layer * h

注意：

捕食者增长必须使用实际摄食量 C，不能使用需求量 U。
不能在这里再次减去捕食死亡、背景损失或捕捞量。
不要再额外添加不依赖食物的 r*B 或 Logistic 鱼类增长项。

本步摄食收益与外部补给在统一提交后才进入库存，
不能在同一轮计算里被下一个物种再次立即利用。

没有摄食收益时，鱼类不能自行增加生物量。
如果一个鱼类物种在所有层都为零，本版不允许凭空恢复。


4. 生物量收支账本

本步未保留在模型活体库中的摄食部分：

Unretained =
    sum_i[(1 - eta_i) * sum_j C[i,j]]

背景损失和 Unretained 进入未显式追踪的分解、呼吸、
碎屑或模型边界输出，不再自动返还 R。

捕捞量离开生态系统。

每一步必须核对：

Total_next - Total_previous
=
sum_k(J_k * h)
- TotalBackground
- TotalCatch
- TotalUnretained

其中 Total 包括所有层的 R、A、B、C、D。

这是开放系统的生物量收支，
不要宣称活体生物量恒定，也不要宣称实现了完整能量守恒。

只允许对极小浮点误差进行有记录的容差处理。
禁止通过大范围 clamp、库存上限、最低保有量或自动补鱼，
掩盖不正确的计算。


六、简化层间分布

完成本步生态更新后，对每个鱼类物种 s 进行分层再分配：

T_s = sum_k X_next[s,k]

theta_s = 1 - exp(-mu_s * h)

X_final[s,k] =
    (1 - theta_s) * X_next[s,k]
    + theta_s * p[s,k] * T_s

三个层必须从同一份更新后快照同时计算。

这一过程只能重新分配已有生物量，不能创造或销毁生物量。
记录每一层的迁移净变化，供界面解释。

这个公式只代表对偏好深度分布的缓慢趋近，
不代表真实游泳路径，也不代表主动追逐食物。
不要将它包装成完整行为模型。


七、简化捕捞

只实现一种持续捕捞方式。

用户选择：
目标鱼类 A/B/C/D；
目标深度层 L1/L2/L3/全部；
捕捞强度 u，范围 0–1；
捕捞开启或关闭。

定义：

F_max = 0.02 /模拟日

对被选中的物种和深度层：

F = u * F_max

其他物种和层：
F = 0

捕捞量必须由第五节的统一移除计算产生。

不要增加：
渔网体积、船只路径、网眼大小、体型筛选、噪声、
逃逸、容量限制、价格或经济系统。

显示每个物种的本期捕获量与累计捕获量，单位为 BU。
说明 u 不是“每次捕获百分比”，而是控制持续损失率。

停止捕捞只将 F 归零。
禁止恢复默认库存或直接生成新鱼。


八、3D 表现与界面

采用清晰、简洁的工程可视化风格。
使用深色水体、适度雾效和明确的深度标尺。
避免重度发光、大量装饰面板和复杂后处理。

3D 区域：

呈现一个被分成三层的长方体水体。
支持旋转、缩放、层边界开关和按物种显隐。

每个“物种 × 深度层”的生物量，
映射为若干可视化鱼群和抽样鱼实例。
使用程序化简单鱼形、实例化网格或点精灵，
不要依赖外部美术资源。

总可见鱼实例预算默认不超过 1500。
鱼群可以采用群中心缓慢游动、局部偏移与轻微摆动。
不实现逐鱼全量邻居搜索。

必须满足：

生态状态是唯一权威数据。
渲染实例没有独立生物量，不能反向修改生态状态。
实例创建、销毁、LOD 和可见性变化不能改变鱼类库存。

生物量下降应使鱼群变稀、变小或减少，
不能每帧重新归一化为固定的满屏鱼数量。

实例只是生物量的抽样表现，不是真实鱼的计数。
生物量为零时不显示该物种的实例。
很低但非零时可显示为“低生物量”，不要声称已发生离散灭绝。

不因可视化中的两条鱼接触而再次扣减生物量。
生态上的捕食已经由统一通量完成。

界面至少包含：

1. 三层水体的 3D 视图。
2. 各物种及 R 的生物量时间曲线。
3. 每个物种的分层生物量。
4. 当前与累计捕获量。
5. 食物网视图，箭头从食物指向消费者。
6. 选中物种的收支明细：
   摄食收益、被捕食损失、背景损失、捕捞损失、
   层间交换、最终净变化。

食物网箭头粗细必须来自实际摄食通量 C/h，
不能只播放与模拟无关的装饰动画。

控制项：

暂停、继续、单步、重置；
推进速度，以“模拟日/现实秒”显示；
捕捞目标、深度层与强度；
外部基础饵料补给倍率，范围 0–2；
显示或隐藏对照曲线。

暂停时停止生态推进。
改变推进速度只改变单位现实时间内执行多少个固定步，
不能改变 dt，也不能改变单位模拟时间内的生物过程。

提供以下实验：

A. 无捕捞基线。
B. 持续捕捞 D。

十一、测试与验收

必须编写并实际运行测试，至少覆盖：

1. 非负性与有限值：
   正常运行和极高捕捞压力下，
   不出现显著负生物量、NaN 或 Infinity。

2. 摄食上限：
   每个捕食者对所有猎物的需求总和不超过 q*B；
   实际摄食量不超过需求量乘 dt。

3. 猎物库存约束：
   多个捕食者和捕捞共同作用时，
   总移除量不超过本步开始时的可用库存。

4. 生物量账本：
   逐步检查第五节的收支恒等式，
   使用与总库存规模相关的浮点误差容差。

5. 无外部输入：
   J=0 时，系统总生物量不能凭空增加；
   某个捕食者没有可食用对象时，摄食收益必须为零。

6. 零库存：
   所有层均为零的鱼类物种不能自动复活。
   单层为零但其他层存在时，可以通过已记录的层间交换增加。

7. 交换与遍历顺序：
   只开启层间交换时，各物种总生物量保持不变。
   正确重排物种与矩阵索引后，更新结果应保持一致。

8. 捕捞记账：
   F=0 时捕获量为零。
   关闭其他过程，只保留固定 F 时，
   结果应符合 B(t)=B(0)*exp(-F*t)。
   捕获量不能被重复扣除。

9. 时间步敏感性：
   用默认初始状态，无捕捞运行 200 个模拟日，
   比较 dt=0.2 和 dt=0.1 的最终状态。
   输出相对向量误差，默认参数下应小于 1%。
   不通过修改显示值或平滑曲线掩盖误差。

10. 长时间运行与表现层独立：
    默认参数无捕捞运行 5000 个模拟日并导出结果。
    报告各物种状态、账本误差和是否出现异常。
    不依靠最低库存或自动补鱼维持共存。
    相同初始条件与干预下，
    改变画面帧率、可见实例预算和相机，
    必须得到相同的生态结果。

数学一致性测试必须有明确断言。
食物网实验则报告实际结果，
不要把预想的故事写成强制通过条件。

如默认参数表现与预期明显不符，
先检查公式、单位、索引和重复记账。
只有确认实现正确后才允许校准参数，
并保留原始配置，记录修改理由与前后结果。
